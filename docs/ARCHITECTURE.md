# Acadia — architecture

How the code is organised. Update this file in the same PR as any
change to module boundaries, the memory map or zero page.

## 1. Layers

```
+---------------------------------------------------------+
| game logic   rules, economy, events, AI, screens        |  platform-independent
+---------------------------------------------------------+
| services     tiles/map, sprites, sound driver, text     |  uses only equates
+---------------------------------------------------------+
| platform     hw_a800.asm, input.asm, interrupt setup    |  swapped for 5200
+---------------------------------------------------------+
```

Game logic never touches hardware registers or OS variables directly.

## 3. Memory map (800XL, XEX)

| Range | Use |
|---|---|
| `$0080-$0087` | ZP: math work area `M_NUM` (3), `M_TMP` (3), `M_OP`, `M_OVF` |
| `$0088-$0089` | ZP: `TPTR` string pointer (`text.asm`) |
| `$008A-$008B` | ZP: `SPTR` P/M pointer (`sprites.asm`) |
| `$008C-$00CA` | Free while BASIC is off; reserved for game ZP (allocate in `acadia.asm`) |
| `$00CB-$00CE` | `ZPTR` (2), `OLDVBD` (2) — in use |
| `$2000-$2FFF` | Code: start-up, services, map and display (`acadia.asm` up to `display.asm`) |
| `$3000-$33FF` | Map font 0 (1K aligned): fixed tiles + coast tiles of the first rows |
| `$3400-$37FF` | Map screen memory (`$3400-$35B7` used: 11 rows × 40); the setup screen uses `$3400-$36E3` while it is up (`GAME_START` redraws the map); the help screen `HELPSCR` is `$35C0-$3777` |
| `$3800-$38FF` | Display lists: `DLIST` (map), `SUDLIST` (setup), `HDLIST` (help) and `TDLIST` (title), same page so one store to `SDLSTL` switches |
| `$3900-$3FFF` | RAM variables (`src/vars.asm`), cleared by `VARS_INIT` at start-up |
| `$4000-$43FF` | P/M graphics, double-line resolution, 1K aligned (`PMAREA`); `$4400-$47FF` spare |
| `$4800-$4BFF` | Map font 1 (the islands need 2 fonts; `mkfont.py` stops if they need more) |
| `$4C00-$4FFF` | Help font `HLPFONT` (generated): fixed tiles at their map codes, 3 × 5 letters and digits at screen code + `HELP_OFS` |
| `$5000-$7FFF` | Code block 2 (`CODE2`): game logic (`economy.asm`, `boats.asm`, `fish.asm`, `weather.asm`, `pirates.asm`, `rebels.asm`, `ai.asm`, `sound.asm`, `music.asm`, `pause.asm`, `help.asm`, `screens.asm`, `news.asm`, `setup.asm`, `title.asm`, `demo.asm`); about `$7900` used so far |
| `$8000-$872F` | Title logo `LOGO` (generated by `tools/mktitle.py` into `title_gfx.asm`): ANTIC mode D, 46 lines of 40 bytes; needs 48K (SPEC), unused after the title screen |
| `$8000-$BFFF` | Free: more code, fonts, music, screens |

Variables: all RAM variables live in one block, `src/vars.asm` at
`$3900`, never inline after code, so the same source can run from a
5200 cartridge (AGENTS.md rule 8). Storage is reserved with `*= *+n`
only, so nothing depends on the loader: `VARS_INIT` clears the block
and sets the few non-zero start values (e.g. `KEY` = `$FF`). This
includes RAM screen memory such as the status lines, which are copied
from a constant template at start-up. Add new variables to `vars.asm`,
grouped by module.

5200 budget: the 5200 has only 16K of RAM (`$0000-$3FFF`), with code
and constant data in cartridge ROM. Screen, display list, P/M graphics,
any RAM-resident font and all variables must fit in roughly 14K. Keep
that in mind before growing RAM buffers.

Constraints: fonts 1K aligned (modes 2/4/5); screen memory must not
cross a 4K boundary without a new LMS; display lists must not cross a
1K boundary; P/M base 1K (double-line) or 2K (single-line) aligned.

## 4. Platform interface

Everything the game needs from the machine, so a 5200 build can
provide the same symbols.

**Input** (`input.asm`, call `INPUT_POLL` once per frame):

| Symbol | Meaning |
|---|---|
| `JOY0`, `JOY1` | Direction bits, 1 = pressed: b0 up, b1 down, b2 left, b3 right |
| `FIRE0`, `FIRE1` | 1 = fire held |
| `KEY` | Item key 0-9 pressed this poll (edge), else `$FF` |
| `KEYPL` | Player the key belongs to: 0 or 1 (D17: fire held picks the player; neither → 0); `$FF` if both held, and then `KEY` is `$FF` too |
| `CONKEY` | START/SELECT/OPTION held bits (b0/b1/b2), for the D18 info displays |
| `PAUSEK` | 1 on the poll where the pause key was pressed (P on the 800, PAUSE on a 5200 keypad), D19 |
| `HELPK` | 1 on the poll where H or the XL/XE HELP key was pressed (help screen, D34) |

Keypad controller (D49): `KP_ON` / `KP_OFF` switch port 2 between a
stick and a keypad (`KPMODE`). With the keypad on, `JOY1` and `FIRE1`
stay 0, its digits come in as `KEY` with `KEYPL` 0, * as `PAUSEK`
and # as `HELPK`. `GAME_START` turns it on for a 1-player game with
KEYPAD set; `SETUP_ENTER` turns it off.

5200 mapping (later): analog sticks thresholded into `JOY*`; keypad
0-9 → `KEY` (per controller); second fire button → mode toggle (key 0)
or info display. See OPEN-QUESTIONS Q4.

**Interrupts:** the game installs a deferred VBI (`VVBLKD`) and a DLI
(`VDSLST`) by writing the RAM vectors with `NMIEN = 0`, then
re-enabling NMIs. The deferred VBI chains to the previous handler via
the saved pointer `OLDVBD`. No OS routine is ever called.

## 5. Frame loop

```
VBI (every frame):   FRAME++, ATRACT=0, sound driver step, sprite positions
Main loop:           wait for FRAME change, then GAME_FRAME:
                     INPUT_POLL
                     setup screen (GS_SETUP): SETUP_FRAME only
                     game over (GS_OVER): OVER_FRAME only
                     HELP_KEY: H / HELP toggles the price list; while
                       it is up skip everything below
                     PAUSE_KEY: P toggles pause; while paused skip
                       everything below except the sprite drawing
                     AI_FRAME (1 player: the CPU's stick and purchase)
                     cursor/boat movement from input, buying (ECO_KEY)
                     if tic due (20 Hz): run TIC tasks
                       news slot timer (NEWS_TIC, in GAME_TIC)
                       fish (FISH_TIC), weather (WTH_TIC) and pirates
                       and boat collisions (PIR_TIC), the CPU (AI_TIC),
                       rounds only
                     FISH_SHOW: draw the schools in P3, fill HP3ROW
                     WTH_SHOW: draw the weather in P2, fill HP2ROW, WCROW
                     PIR_SHOW: draw the pirates in the missiles, fill HMROW
                       once per second: clock
                       end of round: economy, population, score, rebels
                     redraw changed tiles / status fields
```

Rule: anything that writes screen memory or colour registers mid-frame
must be safe against the DLI (only the DLI writes hardware colours; game
code writes RAM copies). The map palette is such a copy: `MAPPAL`, set
by `PAL_NORM` (D16 colours) or `PAL_DIM` (half brightness, pause).

## 6. CPU budget

NTSC frame ≈ 29,800 cycles; with mode 5 + mode 2 DMA and P/M DMA,
assume ~18,000 usable per frame. Targets:

- VBI (sound + sprites): ≤ 2,500 cycles
- Per-tic logic: ≤ 8,000 cycles
- AI decision: ≤ 10,000 cycles, spread over frames if needed
- End-of-round scoring may take several frames (the clock is stopped)

## 7. Data model (game state)

Indexed by player `P` = 0 (left island) or 1 (right island). Keep the
original's layout so the formulas port directly:

| Variable | Size | Notes |
|---|---|---|
| `GOLD[P]` | 16-bit | current gold |
| `POP[P]` | 16-bit | population, cap 9999 |
| `SCORE[P]` | 16-bit | total score |
| `RSCORE[P]`, `PRSCORE[P]` | 8-bit | this / previous round score |
| `RGOLD[P]` | 16-bit | gold earned this round (8-bit in original; widened, R-RULE-8) |
| `COUNT` | 8-bit × 20 | items owned: `COUNT`+k for player 1's item k, `COUNT`+10+k for player 2's |
| `MAPITEM` | 8-bit × 220 | item on each square, 0 = none, 1-9 (RAM); kind + owner in `ISLKIND` and terrain in `ISLTILE` (constant), all 20 × 11, index = row × 20 + column |
| timers | 8-bit | `REMSEC`, `TICSEC`, `CURTRN`, `NUMTRN`, `TRNLEN` |
| event counters | 8-bit | fishing, rain-on-crop, weather damage per player |

The logical grid is the original's 20 × 12 cards (each card = one
island square). On screen each square is 2 × 1 mode 5 characters
(D12); 11 of the 12 rows are visible under the status bar, which is
enough because the islands use about 7-8 rows.

## 8. Naming conventions

- Routines: `MODULE_VERB` (e.g. `MAP_BUILD`, `ECO_INCOME`).
- Internal labels: 2-3 letter module prefix + `_` (e.g. `EC_LOOP`).
- Equates: hardware as in Atari docs; game constants `C_` colours,
  `T_` tiles, `I_` items (1-9 as the original), `MAX_`/`MIN_` limits.

## 9. Map tiles and islands

A map square is one **tile**: two mode 5 characters, 8 × 8 pixels shown
8 colour clocks wide and 16 scan lines tall. Colours per D16: `00` sea
(COLBK), `01` grass (PF0), `10` dark (PF1), `11` yellow (PF2), or white
(PF3) on tiles flagged inverse, whose characters have bit 7 set.

Everything is generated by `tools/mkfont.py` (edit it, rerun
`python3 -I tools/mkfont.py`, never edit the outputs;
`--preview build/preview` also writes PNG previews of the islands,
with and without the beach rim):

- `src/tiles.asm`: fixed-tile and cell-kind equates
- `src/font_map.asm`: the map fonts
- `src/islands.asm`: `TILECH`, `ROWFONT`, `ISLKIND` and
  `ISLTILE` (220 bytes each, row-major, index = row × 20 + column),
  and the CPU's step tables `AI_HD`, `AI_UP`, `AI_DN` (same layout:
  steps by sea, 4 ways, to player 2's harbour, rows 0-1, rows 9-10;
  `$FF` for land)

**Islands (D23, D24).** Each island is a square outline in the generator
(`.` sea, `#` land, `H` harbour, `r` rock). A seeded, deterministic
erosion pass (value noise at 3 and 6 px scales plus per-pixel jitter,
depth 0-3 px from the sea, mostly 1) makes the coast ragged inside the
land squares, which stay about 85-90 % land. It never adds land to a
sea square, keeps each land square's centre, keeps a 4-pixel band
through squares that join land on opposite sides (no thin necks),
keeps the square behind a harbour whole, and fills enclosed lakes. The
generator also rejects sea squares enclosed by land. Harbours sit one
square in from the screen edge (column 1 / 18) so the pier isn't
clipped by overscan. The
bitmap is then cut into 8 × 8 squares and a 1-pixel yellow beach is
drawn on every land pixel that touches sea. Every square with any land
is a land square: buildable, and boats can't enter it. The generator
checks the open sea bands and channel and prints per-island numbers
(land squares, full vs coast squares, land pixels and their share of
the land squares, coastline length, harbour position).

**Tiles and fonts.** Fixed tiles come first and have the same
character codes in every font:

| Tile | Equate | Contents |
|---|---|---|
| 0 | `T_SEA` | Open sea |
| 1 | `T_GRASS` | Plain grass (full land square) |
| 2-10 | `T_ITEM` + k − 1 | Items 1-9: fort, factory, crop, school\*, hospital\*, house, rebel, PT boat, fishing boat |
| 11 | `T_WRECK` | Wreck of a parked boat |
| 12 | `T_SPARE` | Spare (blank) |
| 13 | `T_ROCK` | Rock (decorative) |
| 14, 15 | `T_PIER_W`, `T_PIER_E` | Harbour pier, land to the west / east |
| 16+ | — | Coast squares, unique per position (`N_TILES` in all) |

\* white, drawn with inverse characters.

Coast tiles go into the font of the map row they are on. Consecutive
rows share a font while it fits (64 tiles per font, `N_FIXED` of them
fixed). `ROWFONT` gives each row's font page; the status-bar DLI sets
row 0's font and the map colours, and a DLI at the end of each map row
0-9 (`DLI_ROW`) sets the next row's font. Both also load `HPOSP3` from
`HP3ROW` (the fish player's position for that row, 0 = off screen),
`HPOSP2` from `HP2ROW` and `COLPM2` from `WCROW` (the weather's),
and `HPOSM3`-`HPOSM0` from `HMROW` (the pirates': M3 at `HMROW`, the
others 2, 4 and 6 colour clocks right of it, so the four missiles
make one 8-pixel fifth player); the deferred VBI parks P2, P3 and the
missiles at 0 for the status bar. The deferred VBI resets
`VDSLST` to `DLI_MAP` each frame. `TILECH[t]` is tile `t`'s left
character code in its font (inverse bit included); the right character
is that plus one. Items replace a square's terrain tile on screen;
`ISLTILE` keeps the terrain to restore.

**Cell kinds** (`ISLKIND`): `K_SEA` 0, `K_LAND` 1 (any land: buildable,
blocks boats), `K_HARB` 3 (one per island), `K_ROCK` 4 (plays as sea,
D30); `K_P1` (bit 7) marks player 1's squares.

**Grid ↔ screen** (`display.asm`): `MAP_IDX` (column, row → grid
index), `MAP_PUT` (draw a tile at column, row), `HPOS_COL` (P/M
horizontal position → column, `HP_MAP` = 48) and `PMY_ROW`
(double-line P/M line → row, `PM_MAP` = 24). A normal-width player
covers exactly one square.
